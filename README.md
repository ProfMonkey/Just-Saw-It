# Just-Saw-It「刚刚刷到」🐒

> 一个轻量的电脑端工具：帮你找回“刚刚刷到、却因为刷新而消失”的信息流内容。

## 🎯 为什么做它？

在知乎、小红书这类信息流平台里，经常会出现一种情况：

```
刚刚看到一个很有意思的内容
        ↓
误触下拉刷新 / 页面刷新
        ↓
推荐流变了
        ↓
刚才那条内容找不到了
```

「刚刚刷到」就是为这个瞬间做的。

它不是用来保存你浏览过的一切，而是优先解决一个很具体的问题：

> **刷新之前刚刚看到的内容，刷新以后还能不能找回来？**

## 🚀 当前版本：V0.4.0

目前项目使用**卡片级保存 + 按规范化页面 URL 隔离历史**：知乎、小红书分别识别可见卡片；同一网站的不同页面也不会混在同一个历史列表中。

### 知乎

- ✅ 在知乎页面中识别可见的 `AnswerItem` / `PostItem` 卡片（页面没有匹配卡片时不会生成记录）
- ✅ 只处理当前浏览器视口内可见的卡片
- ✅ 当前视口最多保存 7 张卡片
- ✅ 保存标题
- ✅ 保存正文文字
- ✅ 保存来源 URL
- ✅ 卡片稳定 ID
- ✅ 卡片级去重
- ✅ 刷新保护
- ✅ 自动记录
- ✅ 刷新后可以找回刷新前的推荐内容
- ✅ Edge + Tampermonkey + 知乎真实网页已验证

### 小红书

- ✅ 在小红书页面中识别 `section.note-item` 可见笔记卡片（例如首页 / 探索信息流）
- ✅ 依据真实 DOM 样本，按 `section.note-item` 识别每篇笔记卡片
- ✅ 不再用泛化的 `section` 结构猜测笔记，避免把其他页面区域误认成卡片
- ✅ 只处理当前浏览器视口内可见的卡片，最多 15 篇
- ✅ 优先保存标题链接，其次封面链接，避免误取隐藏占位链接
- ✅ 保存标题、卡片文字、作者、笔记 ID、来源链接及封面图片 URL（页面提供时）
- ✅ 只取封面图片，不把作者头像当成笔记封面
- ✅ 卡片级去重；历史列表顺序与屏幕从上到下的顺序一致
- ✅ 刷新保护模式首次进入时保存当前页首屏可见笔记一次，之后不随滚动持续记录
- ✅ 刷新或离开页面前直接保存当时视口中的卡片，避免依赖临时快照恢复
- ✅ 真正 reload 后不额外抓取刷新后的新首屏；依靠卡片去重避免刷新前已保存的内容重复计数
- ✅ 每个规范化页面 URL 使用独立历史：例如知乎首页、知乎问题页、不同搜索条件互不混合
- ✅ 小红书的临时 `xsec_token` 等追踪参数会从页面身份中排除，避免同一页面仅因令牌变化就产生不同历史
- ✅ 历史保留数量按页面分别计算；默认每页最多 20 条，其他页面不会挤掉当前页面的记录
- ✅ 悬浮按钮和历史面板只显示当前页面的记录数与列表；切换页面后会切换到该页面独立的历史
- ✅ 首次升级时，会把旧版首页历史迁移到对应首页的页面历史；其他页面不会继承首页旧记录
- ✅ 刷新保护与自动记录均接入卡片提取
- ℹ️ 页面身份按规范化后的完整 URL 区分；小红书详情页只有在页面中存在可识别的 `section.note-item` 卡片时才会保存卡片，不会自动把整篇详情正文当作卡片
- ⚠️ V0.4.0 已完成静态语法检查；不同知乎 / 小红书页面的实际 DOM 仍需在 Edge + Tampermonkey 中逐页验收
- ℹ️ 当前只保存封面图片 URL，不会把图片文件下载到本地

## 🧠 两种记录模式

### 🔴 刷新保护

这是项目当前最核心的模式。

打开一个页面后，会尝试保存当前视口可见的卡片一次；之后不会因为你一路向下浏览就不断保存大量历史。刷新或离开前会直接保存当时视口中的卡片。刷新后不再额外抓取新首屏，避免刷新后数字突然跳增。每个页面的记录单独保存。

程序重点关注：

> **如果你刷新了，现在屏幕上的内容能不能在刷新后找回来？**

适合：

> “我只是怕刚才看到的东西被刷新没了。”

### 🟢 自动记录

持续检测新的可见内容。

适合：

> “我希望把刚刚刷到的新内容持续留下来。”

## 📦 当前工作方式

```
知乎 / 小红书页面（仅处理匹配到的卡片）
        ↓
   识别当前页面
        ↓
  提取刚刚看到的内容
        ↓
   本地保存历史
        ↓
     用户刷新
        ↓
   打开「🐒 历史」
        ↓
   找回刚才的内容
```

当前版本坚持一个原则：

> **先把核心需求做对，再增加功能。**

## 🛠️ 安装

本项目目前是**电脑端 Tampermonkey Userscript 原型**，不是独立浏览器扩展，也不是 Android App。

### 1. 安装 Tampermonkey

在 Edge 或 Chrome 中安装 Tampermonkey（油猴）。

### 2. 安装脚本

打开仓库里的 'just-saw-it.user.js'。

复制完整代码，粘贴到 Tampermonkey 的新脚本中，然后：

```text
Ctrl + S
```

### 3. 打开网站

打开：

- 知乎首页
- 小红书首页 / 探索页

脚本生效后，页面右下角会出现：

```text
🐒 历史
```

## 🧪 推荐测试方法

### 测试知乎刷新保护

1. 打开知乎首页
2. 点击「🐒 历史」
3. 清空历史
4. 选择「刷新保护」
5. 保持当前页面不动几秒
6. 刷新知乎
7. 打开「🐒 历史」
8. 检查刷新前看到的推荐内容是否还能找到

### 测试知乎滚动

1. 清空历史
2. 保持「刷新保护」或切换到「自动记录」
3. 向下滚动
4. 查看历史中是否出现新的可见推荐内容
5. 检查不会一次保存大量屏幕之外的卡片

当前知乎 extractor 的策略是：

> **只处理当前视口内的卡片，并最多取 7 张。**

### 测试小红书刷新保护（V0.4.0）

1. 在 Edge 中打开小红书网页版的推荐 / 探索信息流。
2. 点击「🐒 历史」，清空历史并选择「刷新保护」。
3. 确认当前屏幕上能看到多篇笔记，记住其中 2–3 篇标题。
4. 按 `Ctrl + R` 刷新页面。
5. 再次打开历史，确认刷新前的笔记标题、卡片文字和来源链接能够找回。
6. 检查历史中没有导航栏、登录提示或整页拼接文字充当笔记。
7. 切换「自动记录」，向下滚动一屏，检查新出现的可见笔记能否记录，且同一篇不会反复新增。
8. 如果某些笔记没有标题、链接或封面，请截图并反馈；不要据此直接扩大选择器到整个页面。

小红书当前只从 `section.note-item` 提取笔记，最多处理视口内 15 篇；优先读取标题链接与封面图片。**代码已实现，但只有完成上述 Edge 实测后，才能确认选择器适配了你当前看到的小红书页面。**

## 🔐 隐私

当前版本使用 Tampermonkey 的本地存储能力保存历史。

项目本身：

- 不需要账号
- 不需要服务器
- 不主动上传历史内容
- 不需要云同步
- 不主动读取私信
- 不主动读取聊天内容
- 不保存整篇页面或详情正文；只保存页面中匹配到的可见卡片

不过，脚本保存的是网页上实际显示的内容，因此历史记录中仍可能出现网站展示的个人信息。

**不要在公共电脑上保存敏感内容。**
